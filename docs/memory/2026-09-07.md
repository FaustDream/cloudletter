## 灵感笔记增加使用状态（待使用/已使用/已过期）

### 需求背景

用户反馈：灵感笔记一直堆积，不知道每条处于什么状态（是否已使用/已过期），需要一个显式的状态字段来标记。

### 决策

- 状态机只保留用户可控的三种状态：`pending`（待使用，新建默认）/ `used`（已使用）/ `expired`（已过期）；不引入自动过期逻辑（不依赖日期自动翻转），由用户手动标记，语义干净。
- 状态字段放在 `NoteItem.status`（String + default 'pending'），**纯新增列、带默认值，`prisma db push` 非破坏性**，走 DEPLOY.md §3 标准流程即可，无需中间态/迁移脚本三段法。

### 改动内容

- **schema**：`server/prisma/schema.prisma` NoteItem 增加 `status String @default("pending")` + 注释。
- **后端** `server/src/routes/workbench.ts`：
  - `WB_SCHEMA.notes` 增加 `status: oneOf ['pending','used','expired']`（非法值 422）；
  - `FIELDS.notes` 白名单加入 `status`；
  - `createNote` 缺省 pending、`updateNote` 支持改 status；
  - `NoteWithTax` 增加 status，`shapeNote` 透出。
  - 时间轴灵感节点：非「待使用」的笔记预览加前缀（`已使用 · …` / `已过期 · …`），pending 不带前缀保持干净。
- **前端**：
  - `apps/workbench/src/api.ts`：新增 `NoteStatus` 类型，`NoteItem.status`。
  - `NotesPage`：卡片元信息行加状态徽标（`.nst.st-pending` 信息蓝 / `.st-used` 成功绿 / `.st-expired` 警示琥珀）；页头新增「全部/待使用/已使用/已过期」状态筛选（`statusFilter` 过滤）；编辑抽屉分类/状态/标签三列并排（g-3），状态 Dropdown 随时改；新建默认 pending。
  - `QuickNoteModal` 不改（创建不传 status，服务端兜底 pending）。
- **样式**：`apps/workbench/src/styles/main.css` 状态徽标三色，沿用 `--info/--ok/--warn` 语义色 + color-mix 浅底。

# 2026-09-07（四）：随手记三项根治（撤销根因确诊 · Notion 式下拉 · 高度自适应，已上站）

## 根因确诊（① 打字被撤销）

- 上轮（三）只在速记弹窗（QuickNoteModal）验证过逐键输入，且结论为旧 bundle——本轮用户再次反馈后复核：**灵感笔记页编辑抽屉（NotesPage）与速记汇总页编辑弹窗（QuickNotesPage）仍是受控编辑器**，同类 bug 的修复从未覆盖这两处，用户口中的「随手记（灵感）」正是这两个入口。
- 受控链路里唯一能「无用户操作改写正文」的路径 = 外部值回灌 `replaceFromMarkdown` → `editor.replaceBlocks()`；该事务同时写入 ProseMirror 撤销历史，所以表现就是「触发了撤销」。`value === lastEmitted` 字符串短路只护住快乐路径：300ms 防抖上抛 × `blocksToMarkdownLossy` 异步序列化 × 父组件 setState 交织时可能错位，回灌一旦发生在编辑会话内就会重置当前输入，且 value/lastEmitted 轮流更新可往复触发（对应「触发按键一直被触发」）。另外挂载时初次 replaceBlocks 也在撤销历史里，打开后一步撤销即回空文档（对应「文字还在但被撤销」）。
- 修法（与 QuickNoteModal 同款）：两处编辑表单一律 `uncontrolled`（value 仅初值、外部永不回灌）——抽屉/弹窗均为一次性编辑场景，value 只在打开时由 openNote/openCreate 设置，body 只经编辑器自身 onChange 更新，受控回灌在会话内本就无用。

## ② Notion 式下拉（标签/分类）

- NotesPage 抽屉（g-3：分类/状态/标签）与 QuickNotesPage 弹窗（g-2：分类/标签）：分类=TagMultiSelect 单选（`multiple={false}` + onCreate→POST /categories 落库并同步候选）、标签=TagMultiSelect 多选（候选=GET /tags 全站标签池），均可搜索、无命中直接新建；表单结构 `categoryId/tags(string)` → `categoryName/tagNames(string[])`，保存时按名解析。
- 分类名→id 解析三处收敛为 `lib/taxonomy.ts` `resolveCategoryIdByName(cats, name, create)`（命中返回既有 id / 未命中走 create 落库 / 空名与失败返回 '' 不阻断保存），QuickNoteModal 同步改为调用共享实现。
