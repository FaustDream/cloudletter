# 2026-09-08：邮件链接 origin 修复（已上站）

## 用户报障

忘记密码邮件链接为 `http://localhost:3011/login?reset=...`（后端端口），打开显示 `{"error":{"code":"NOT_FOUND","message":"接口不存在"}}`；并问生产环境是否一样。

## 根因

- `auth.ts send-reset` / `grants.ts POST /` / `rss.ts GET /rss.xml` 三处的 origin 都是 `${req.protocol}://${req.get('host')}`——取 **API 请求的 Host 头**。
- 本地：vite 代理 `changeOrigin: true` 把 Host 改写为后端端口（localhost:3011）→ 链接指向后端；`/login` 是前端 SPA 路由 → Express 兜底返回应用级 404「接口不存在」。
- 生产不一样：nginx `location /api/` 配了 `proxy_set_header Host $host`，后端拿到的 Host = 公网访问地址（121.37.222.241），链接 `http://121.37.222.241/login?...` 经 `location /` SPA 兜底正常打开——**生产一直正常，无需处理历史邮件以外的东西**。

## 修复

- 新增 `server/src/lib/webOrigin.ts`：`WEB_ORIGIN` env（服务器显式配置，最高优先，尾斜杠归一）> 请求 `Origin` 头（浏览器 fetch 天然携带 = 真实前端站点；畸形值/"null"/带路径忽略）> API Host 兜底（与原行为一致）。
- 三处统一接入 `webOrigin(req)`；服务器可选在 `.env.production` 加 `WEB_ORIGIN` 加固（不配也正确）。

# 2026-09-08（二）：SMTP 发送失败从 500 改为明确 503 + 弹窗去 ×（已上站）

## 根因（日志确诊）

- `journalctl`：`Invalid login: 535 Login fail...`（QQ 邮箱 SMTP）——**SMTP 账号登录失败**（授权码失效/账号异常/限频/服务未开），与 origin 修复无关（部署前 09:23 即在报错）。

- 根因：`.sidebar .foot { opacity: .7 }`——菜单从侧栏底部头像弹出、DOM 属于 foot 子树，**祖先级 opacity 作用整棵子树**（子元素 opacity:1 无法逃逸，L343 的旧补救无效），菜单整体 70% 不透明 → 页面文字透出。

## 根因分析：为什么之前规范没被遵守

1. **规范不可执行**：原约束只有一句「样式遵循 theme.css」——没有可查的阶梯表（字号该取哪些值？z-index 分层是什么？），人/agent 写样式时无表可查，只能即兴拍字面量。**教训：约束必须落成可查表（§9.3），而非一句原则。**
2. **无自动门禁**：紫色/硬编码 violations 靠人肉 review，从未被系统性扫描过，长期静默积累。**教训：🔴 级约束必须配 checker 并接入 build 前置（§9.4），「写进文档」≠「被执行」。**
3. **双轨真相源**：`shared/theme.css` 与 `main.css` 并存且 AGENTS 指向前者，实际代码全在后者——规范指向与事实脱节没人发现，因为「零引用文件」从未被审计。**教训：真相源唯一且规范指向必须与 grep 结果一致。**
4. **组件级 dark 补丁合理化惯性**：暗色适配最初是「哪坏补哪」，补丁积累成第二套体系。**教训：暗色适配必须走成对令牌（组件级成对覆写），组件内 dark 补丁禁止入仓。**
